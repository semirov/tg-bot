# Telegram Memes Bot

[![Demo](https://img.shields.io/badge/demo-filipp__memes__bot-blue?style=flat-square&logo=telegram)](https://t.me/filipp_memes_bot)
[![Channel](https://img.shields.io/badge/channel-filipp__memes-blue?style=flat-square&logo=telegram)](https://t.me/filipp_memes)
[![coverage](./coverage-badge.svg)](COVERAGE.md)

Telegram бот для управления мемами и предложкой канала. Позволяет пользователям отправлять мемы на модерацию, а модераторам управлять публикацией контента.

**Реальный работающий бот**: [@filipp_memes_bot](https://t.me/filipp_memes_bot)
**Реальный канал**: [@filipp_memes](https://t.me/filipp_memes)

### Основные модули

#### 1. Модуль бота (`bot/`)
Содержит всю логику взаимодействия с Telegram API:
- **Провайдеры**: Инициализация бота, middleware
- **Сервисы**: Управление пользователями, запросами, планировщиком, настройками
- **Сущности**: Пользователи, запросы, сессии, настройки
- **Интерфейсы**: Контекст бота

#### 2. Модуль управления постами (`post-management/`)
Отвечает за обработку пользовательских постов:
- **Сервисы**: Управление постами пользователей, обращения к админу
- **Константы**: Режимы публикации, меню модерации

#### 3. Модуль меню (`menus/`)
Управление интерфейсом бота:
- **Сервисы**: Главное меню, меню администратора, модератора

#### 4. Модуль обсерватории (`observatory/`)
Система модерации контента:
- **Сервисы**: Управление постами обсерватории
- **Сущности**: Посты обсерватории

Парсер источников (модуль `client/`, MTProto userbot) находит медиапосты в чужих каналах и
форвардит их **напрямую в личку боту** (канал-коллектор больше не используется). Бот принимает
посты от аккаунта `PARSER_USER_ID` **без капчи и без проверки подписки**, копирует их в предложку
с подписью источника и меню модерации. Парсер отсекает рекламу по ссылкам (`AdDetector`) и
пересылает фото и видео.

#### 5. Модуль итогов года (`year-results/`)
Автоматическая генерация и публикация статистики за год:
- **Сервисы**: Сбор статистики, форматирование сообщений, публикация
- **Сущности**: Результаты года для пользователей
- **Интерфейсы**: Типы данных статистики

#### 6. Модуль конфигурации (`config/`)
Управление настройками приложения:
- **Сервисы**: Базовая конфигурация
- **Конфигурации**: Переменные окружения

#### 7. LLM-модуль (`llm/`)
Нейтральный клиент DeepSeek (OpenAI-совместимый `/chat/completions`), который
использует AI-ступень парсера: классификация каналов-кандидатов и префильтр
подписей постов.

- **Модель**: `DEEPSEEK_USE_PRO_MODEL` выбирает `deepseek-v4-pro`, иначе
  `DEEPSEEK_MODEL` (по умолчанию `deepseek-flash`); vision всегда идёт на
  `DEEPSEEK_VISION_MODEL`;
- **Защита от перерасхода**: жёсткий потолок `max_tokens`, лимит одновременных
  запросов и суточный лимит (`DEEPSEEK_DAILY_REQUEST_LIMIT`);
- **Учёт расхода**: количество запросов, токенов и стоимость за сутки по
  официальному тарифу DeepSeek (с разбивкой по кэшу и пик/off-peak).

### Переменные окружения

Создайте файл `.env` в корне проекта:

```env
# Telegram Bot
BOT_TOKEN=your_bot_token
BOT_OWNER_ID=your_telegram_id

# Channels
MANAGED_CHANNEL=your_channel_id
USER_REQUEST_CHANNEL=request_channel_id
CRINGE_CHANNEL=cringe_channel_id

# Парсер источников (userbot). Его посты в личке бот принимает без капчи
# и кладёт в предложку. Не задан — приём от парсера выключен.
PARSER_USER_ID=your_parser_user_id

# Мастер-выключатель параллельного парсера (Source Registry → отбор → сетка
# «Парсер» в предложке). По умолчанию включён; false — полностью выключить.
# PARSER_ENABLED=true

# Database
DATABASE_HOST=localhost
DATABASE_PORT=5432
DATABASE_USERNAME=postgres
DATABASE_PASSWORD=postgres
DATABASE_NAME=memes_bot

# Telegram API
APP_API_ID=your_api_id
APP_API_HASH=your_api_hash

# DeepSeek (LLM-клиент: AI-классификация парсера)
DEEPSEEK_API_KEY=your_deepseek_key
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash
DEEPSEEK_REASONING_EFFORT=none
# DEEPSEEK_USE_PRO_MODEL=true
# DEEPSEEK_DAILY_REQUEST_LIMIT=2000

# Environment
TG_ENV=prod
```

#### Описание переменных окружения

**Telegram Bot:**
- `BOT_TOKEN` - Токен Telegram бота, полученный от BotFather
- `BOT_OWNER_ID` - Telegram ID владельца бота (администратора)

**Channels:**
- `MANAGED_CHANNEL` - ID основного канала для публикации мемов
- `USER_REQUEST_CHANNEL` - ID канала предложки для модерации постов
- `CRINGE_CHANNEL` - ID канала для публикации кринж контента
- `PARSER_USER_ID` - ID аккаунта-парсера (userbot). Посты, которые парсер форвардит боту в
  личку, принимаются **без капчи и без проверки подписки** и уходят в предложку с подписью
  источника. Если не задан — приём от парсера выключен

**Database:**
- `DATABASE_HOST` - Хост базы данных PostgreSQL
- `DATABASE_PORT` - Порт базы данных PostgreSQL
- `DATABASE_USERNAME` - Имя пользователя для подключения к БД
- `DATABASE_PASSWORD` - Пароль для подключения к БД
- `DATABASE_NAME` - Название базы данных

**Telegram API:**
- `APP_API_ID` - API ID приложения Telegram (https://my.telegram.org)
- `APP_API_HASH` - API Hash приложения Telegram (https://my.telegram.org)

**DeepSeek (LLM-клиент):**
- `DEEPSEEK_API_KEY` - ключ DeepSeek; без него AI-функции парсера отключены, остальное работает
- `DEEPSEEK_BASE_URL` - адрес API (по умолчанию `https://api.deepseek.com`)
- `DEEPSEEK_MODEL` - рабочая модель, по умолчанию `deepseek-flash`
- `DEEPSEEK_USE_PRO_MODEL` - `true` (по умолчанию) выбирает `deepseek-v4-pro`, иначе `DEEPSEEK_MODEL`
- `DEEPSEEK_DAILY_REQUEST_LIMIT` - суточный лимит запросов (0 = безлимит; по умолчанию 2000)
- `DEEPSEEK_REASONING_EFFORT` - режим «размышлений» модели (`none` | `minimal` | `low` | `medium` | `high`).
  По умолчанию `none`: `deepseek-flash` — reasoning-модель, и на коротких бюджетах размышления
  съедают весь ответ целиком, из-за чего приходили пустые сообщения

**Environment:**
- `TG_ENV` - Окружение запуска (`prod` или `test`)

## 🛠️ Основные функции

### Для пользователей

1. **Отправка мемов**: Пользователи могут отправлять изображения и видео в бота
2. **Лимиты**: Ограничение на 5 постов в сутки
3. **Обращения к админу**: Возможность отправки текстовых сообщений администратору
4. **Капча**: Защита от ботов при первом взаимодействии

### Для модераторов

1. **Модерация постов**: Интерфейс для одобрения/отклонения постов
2. **Планирование публикаций**: Различные режимы публикации (ночь, утро, день, вечер)
3. **Управление лимитами**: Возможность временного снятия ограничений с пользователей
4. **Дедупликация**: Автоматическое обнаружение дубликатов постов

### Системные функции

1. **Планировщик**: Автоматическая публикация постов в заданное время
2. **Пользовательские посты — в ближайший зазор**: предложенные пользователями посты не уезжают в конец очереди, а вставляются в середину ближайшего свободного промежутка между постами парсера/обсерватории (по одному на промежуток, с суточным потолком), чтобы авторы видели свой пост скоро и канал не заваливало
3. **Дедупликация**: Предотвращение публикации одинаковых изображений
4. **Статистика**: Отслеживание активности пользователей
5. **Крон задачи**: Регулярные операции по обслуживанию
6. **Алерт о пустеющей очереди**: владельцу в личку приходит уведомление, когда очередь публикации заполнена меньше чем на ~3 дня, на ~1 день или пуста (только днём 09:00–23:00 МСК, не чаще раза в сутки на уровень)
7. **Итоги года**: Автоматическая генерация и публикация статистики за год

### Итоги года

Модуль автоматически генерирует и публикует статистику за год:

#### Общая статистика (публикуется в канал):
- Всего опубликованных постов
- Количество авторов
- Активные дни
- Самый продуктивный день
- Самый активный/спокойный месяц
- Популярное время публикации
- Статистика по дубликатам
- Обезличенные данные о лидерах

#### Персональная статистика (отправляется пользователям):
- Количество предложенных и опубликованных постов
- Процент одобрения
- Активные дни и серии
- Среднее время до публикации
- Самое активное время суток
- Статистика по дубликатам

#### Команды администратора:
- `/year_result` - Генерация и предпросмотр итогов года
- `/year_result_publish` - Публикация итогов в канал и отправка пользователям

#### Автоматическая генерация:
- Каждое 25 декабря в 10:00 автоматически генерируются итоги года
- Preview отправляется владельцу бота для проверки
- Публикация выполняется вручную командой `/year_result_publish`

#### Особенности:
- Статистика собирается за календарный год
- Персональные итоги отправляются только пользователям с опубликованными постами
- Задержки между отправками для избежания rate limits
- Автоматическая обработка заблокированных пользователей
- Механизм повторных попыток при временных ошибках

## 🧭 Парсер источников (по требованию)

Модуль `parser/` — второй контур сбора контента, работает параллельно с
обсерваторией. Посты попадают в предложку отдельной сеткой «🧭 Парсер».

**Главное отличие от старой модели: предложка не наполняется потоком.** Посты
выдаются пачкой по запросу:

- кнопка **«🍲 Ещё 20»** на последней карточке в предложке, или
- канал-пост в канале предложки: **`/more`**, а также `ещё`, `еще`, `больше`,
  `насыпь` (только в канале модерации).

За раз — до 20 постов, **свежие первыми**, **не больше 3 с одного канала**
(разнообразие). Исключение — **форс-посты**: если один и тот же пост встретился
в 3+ каналах за 48 ч, он уходит сразу, без скоринга, с пометкой «⚡️ форс».

Динамика интереса берётся из модерации: взял пост (Сейчас/Очередь/Ночь) — канал
поднимается и предлагается чаще; отклонил — жёсткий игнор; истёк в бэклоге —
мягкий. Положительный рейтинг **остывает**: буст тает вдвое за 21 день без
взятий, а через 45 дней история взятий делится пополам.

Прочее: дедуп предложки (старая необработанная карточка удаляется, остаётся
нижняя, подпись «первый источник · +N»; видео — по обложке), чёрный список
источников с подтверждением, авто-discovery без ручных карточек, сбор нового
источника не глубже 48 ч, старение бэклога (карточки 7 дней, пул 14 дней),
тумблер «Старый парсер» (гасит приём постов обсерваторией, не трогая юзербот).

Полное описание архитектуры, сущностей, символов и констант — в
[`apps/memes-bot/src/app/modules/parser/README.md`](apps/memes-bot/src/app/modules/parser/README.md),
легенда для пользователя — в TGB-DOC-7.

### Меню «🧭 Парсер» (админ-меню, только владелец)

Конвейер вкл/выкл, **👴 Старый парсер**, ERR min, «Финал через N ч», AI-тумблер,
импорт подписок, пагинированные списки **🏆 Популярные / 🚫 Исключённые /
📚 Все источники**, сброс.

### Кнопки карточки «Парсер»

`▶️ Сейчас` (публикация с ссылкой на источник), `📋 В очередь`
(`NEXT_INTERVAL`, считается опубликованным), `🌙 В ночь (кринж)`
(`NIGHT_CRINGE` + перенос в кринж-канал после 6:00), `🗑 Отклонить`,
`🚫 Исключить источник` (с подтверждением → вечный чёрный список).
После постановки в сетку кнопка с датой — снятие с публикации (с подтверждением).

Админ-меню «📅 Сетка публикаций» — пагинированный список неопубликованных
постов (ближайшие первыми) со ссылками и снятием; списки источников — со
ссылками на каналы и исключением/возвратом.

## 🔧 Конфигурация

### Режимы публикации

- `NOW_SILENT`: Немедленная публикация
- `NEXT_INTERVAL`: Ближайший доступный слот
- `NIGHT_CRINGE`: Ночная рубрика кринжа
- `NEXT_MORNING`: Утренняя публикация
- `NEXT_MIDDAY`: Дневная публикация
- `NEXT_EVENING`: Вечерняя публикация
- `NEXT_NIGHT`: Ночная публикация

### Права пользователей

- `IS_BASE_MODERATOR`: Базовые права модератора
- `ALLOW_PUBLISH_TO_CHANNEL`: Публикация в канал
- `ALLOW_DELETE_REJECTED_POST`: Удаление отклоненных постов
- `ALLOW_RESTORE_DISCARDED_POST`: Восстановление отклоненных постов
- `ALLOW_SET_STRIKE`: Установка страйков
- `ALLOW_MAKE_BAN`: Бан пользователей

## 📈 Мониторинг и логирование

Приложение использует встроенный логгер NestJS для отслеживания:
- Ошибок обработки сообщений
- Проблем с базой данных
- Ошибок API Telegram
- Событий модерации
- Расхода DeepSeek: каждая строка лога содержит время ответа, число токенов и **стоимость за сутки**

Логи ротируются: суточный дамп с ограниченным числом хранимых файлов, а вывод контейнера ограничен по размеру.

Проект покрыт юнит-тестами (порог покрытия **95%**, отчёт в [`COVERAGE.md`](COVERAGE.md)) и e2e-тестами на реальном приложении.

### Юнит-тесты

```bash
npm run test:memes-bot     # nx test
npm run coverage           # тесты + покрытие (порог 95%)
npm run coverage:report    # COVERAGE.md + coverage-badge.svg
```

### E2E

E2E поднимает **реальное Nest-приложение и реальный grammY Bot**, но без сети: Bot API мокается каноничным трансформером `bot.api.config.use` (в node-сборке grammY ходит через `node-fetch`), внешние границы (axios, MTProto `telegram`, DeepSeek) замоканы, а состояние — реальный Postgres. Входящие апдейты прогоняются через `bot.handleUpdate`.

Покрыто: онбординг/капча/меню, post-management (предложка, лимиты, дубли, модерация, публикация), observatory (в т.ч. user-moderation), MTProto-клиент (наблюдение канала, auth, ad-detection, альбомы, daily best), парсер, cron и итоги года.

```bash
npm run e2e:docker   # docker compose: Postgres + приложение + прогон e2e
```

Весь тестовый контур контейнеризован: `Dockerfile.test` + `docker-compose.test.yml` (Postgres c `pg_trgm`).

## 🔁 CI/CD и версионирование

CI/CD — GitHub Actions. Пайплайн:

- **PR**: `lint` → юнит-тесты с покрытием (порог 95%) → сборка прод-образа → **e2e**.
- **push в `main`**: то же плюс **semantic-release** (версия из conventional commits, git-тег) и **деплой**; при неудачном старте приложения — автоматический откат на предыдущий образ.
- **Версионирование**: версия вычисляется автоматически (`feat` → minor, `fix`/`perf` → patch), тег `vX.Y.Z`; прокидывается в приложение как `APP_VERSION` и попадает в уведомление владельцу при старте.
- **Сборка**: базовые образы зависимостей собираются отдельным job'ом только при изменении `package-lock.json`; прод-образ собирается один раз в test-job и переиспользуется деплоем. Кэш `nx` — через BuildKit.
- **Секреты**: в репозитории не хранятся; доступы к деплою передаются в CI из защищённого окружения и в код не попадают.

Скрипты пайплайна и деплоя: `tools/ci/build-base.sh`, `tools/ci/release.sh`, `tools/deploy/deploy.sh` (конфигурация окружения — вне репозитория).
