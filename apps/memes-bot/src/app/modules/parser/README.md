# Парсер источников (модуль `parser`)

Второй контур сбора мемов: юзербот (MTProto) читает каналы-источники, бот
оценивает посты и **по запросу** кладёт их карточками в предложку. Работает
параллельно с обсерваторией; в предложке это сетка «🧭 Парсер».

Пользовательская легенда (что значат цифры и символы) — в TGB-DOC-7.
Архитектурная история и задачи — TGB-46, TGB-PLAN-9.

---

## 1. Идея: по требованию, а не потоком

Раньше парсер лил посты в предложку по квотам (K/сутки, кап на источник).
На живом реестре каналов это давало вал, и «не пропустить хорошее» превращалось
в «зашумить всё». Теперь:

- **Ничего не льётся само.** Выдача запускается вручную:
  - кнопкой **«🍲 Ещё 20»** на последней карточке в предложке;
  - канал-постом в канале предложки: **`/more`**, а также `ещё`, `еще`, `больше`,
    `насыпь` (работает только в канале модерации).
- **Исключение — форс-посты** (см. §6): разошлись по 3+ каналам — уходят сразу.

Плюсы: предложка = твоя выборка в удобном темпе; бэклог не растёт бесконечно.
Минус: если не просить — ничего не придёт (в меню видно счётчик бэклога).

## 2. Конвейер

```
Discovery ─▶ Registry ─▶ Collector (live + history sweep)
                                   │
                                   ▼
                              Evaluator  (pre t+2ч / final t+12ч, nv/nr по базлайну)
                                   │
                ┌──────────────────┴───────────────────┐
                ▼                                      ▼
        Форс-посты (3+ канала)                  Пул SCORED (бэклог)
        уходят сразу, без скоринга               │
                │                                ▼
                │                         Dump «Ещё 20» / `/more`
                └──────────────▶ Delivery ─▶ карточка в предложке
                                             │  (дедуп/склейка, форс-метка)
                                             ▼
                                    Модерация (Сейчас/Очередь/Ночь/Отклонить/Исключить)
                                             │
                                             ▼
                                    Обучение веса источника + дедуп опубликованного
```

- **Collector** — live-события юзербота по реестру + history sweep каждые 30 мин
  за окно 26 ч; альбомы копятся дебаунсом. Для **нового** источника история не
  глубже **48 ч**.
- **Evaluator** — перечитывает пост (`getMessages`), нормирует просмотры/реакции
  по медианам канала (`nv = views/vmed`, `nr = reactions/rmed`), ставит `score = nv + nr`.
  Pre-оценка с t+2ч, финал с t+12ч. Перед обычной оценкой всегда прогоняется
  `promoteForced()`; если бэклог предложки > `EVAL_PAUSE_BACKLOG` (400), обычная
  оценка пропускается, чтобы не жечь юзербот впустую.
- **Delivery** — юзербот read-only качает байты, бот публикует карточку.
- **Discovery** — кросс-ссылки из постов → проверка `t.me/s` + ERR → **авто-добавление**
  (web-only), без ручных карточек кандидатов.

## 3. Сущности

| Сущность | Что хранит |
|---|---|
| `SourceChannelEntity` | канал-источник: `chatId/rawChatId/username/title`, `category` (memes/cringe), `status` (active/web_only/disabled), `baseline` (vmed/rmed/p90/posShare), `err`, `subscribers`, вес и интерес: `takenTotal`, `lastTakenAt`, `ignoredTotal`, `softIgnoredTotal`, `lastIgnoredAt`, `weight`, `cooldownUntil`, `cooldownCount`, blacklist: `excluded`, `excludedAt` |
| `ObservedPostEntity` | кандидат-пост: метрики (`views/reactions/metrics/score`), `status`, `evalStage`, `rejectReason`, хеши (`imageHash` 16-бит, `perceptualHash` 64-бит), дедуп/склейка (`duplicateOfId`, `extraSources`, `rootSourceChatId/Title/Username`), `forced`, id сообщения в предложке (`requestChannelMessageId`), `publishedMessageId` |
| `SourceCandidateEntity` | аудит discovery: найденный канал, `mentions`, `verdict`, `reason`, `attempts` |
| `ParserSettingsEntity` | настройки парсера (singleton id=1) |

## 4. Статусы кандидата

```
pending ──eval──▶ scored ──dump/force──▶ selected ──delivered──▶ queued/published
   │                 │                      │            │
   ▼                 ▼                      ▼            ▼
 expired           rejected               failed      duplicate
(pool-14d)      (пороги/модерация)     (retry/terminal)
```

- `pending` — собран, ждёт pre/final оценки (TTL `candidateTtlHours`, дефолт 96ч).
- `scored` — оценён и лежит в пуле; живёт `POOL_TTL_DAYS` (14д), потом `expired pool-14d`.
- `selected` — клейм перед доставкой; «зависшие» без `requestChannelMessageId`
  старше часа возвращаются в `scored`.
- `delivered` — карточка в предложке; старше `BACKLOG_TTL_DAYS` (7д) удаляется
  (`expired backlog-7d` + мягкий игнор источника).
- `queued`/`published` — **считаются опубликованными**: хеш уходит в
  published-дедуп, повторно не предлагаются.
- `duplicate` — либо уже публиковалось (`published-duplicate`), либо вытеснено
  новой карточкой (`superseded-by-<id>`).

Причины отказа смотри в TGB-DOC-7 §6.

## 5. Скоринг и пороги

Абсолютные числа несравнимы между каналами, поэтому сравнение идёт с базлайном
канала (медианы последних постов):

| Метрика | Формула |
|---|---|
| `nv` | просмотры / `vmed` |
| `nr` | реакции / `max(RMED_FLOOR, rmed)` |
| `posShare` | доля положительных реакций среди распознанных (нет данных → не штраф) |
| `score` | `nv + nr` |

Дефолтные пороги (мягкие — «предлагать всё подряд», решение за модератором):
`minViews=100`, `minReactions=1`, `nvMin=0.8`, `nrMin=1`, `posShareMin=0`,
`hotScore=2`. Кринж-категория оценивается иначе (`cringeMinViews=50`,
`cringeShareMin=0.05`).

Ранний выход: score ≥ `hotScore` уже на pre — пост попадает в пул раньше финала.

## 6. Форс-посты

Если одно и то же медиа (`mediaUniqueId`) встретилось в **3+ разных каналах** за
`FORCE_WINDOW_HOURS` (48ч) — все такие кандидаты помечаются `forced` и идут в
предложку **сразу, без скоринга** (`promoteForced()` в оценщике).

Ограничения: форс **не обходит** чёрный список и ERR источника; форс-посты
**игнорируют cooldown** источника; в подписи стоит «⚡️ форс».

Ограничение метода: `mediaUniqueId` ловит точные Telegram-копии/форварды;
ре-аплоады (другой id) форсом не считаются — для них работает склейка по
перцептивному хешу (§7).

## 7. Дедупликация и склейка

Два механизма:

1. **Против опубликованного** (`published_post_hashes`): при доставке считается
   `imageHash ?? perceptualHash`, сравнение — **по одинаковой длине хеша**
   (`checkDuplicateSameLength`), чтобы 4-символьные фото-хеши не «совпадали» с
   16-символьными видео. Совпало → `duplicate published-duplicate`.
2. **Склейка карточек предложки**: если похожий мем уже лежит **необработанной**
   карточкой (`delivered`), старая карточка **удаляется** (`deleteMessage`, при
   сбое — пометка «🚫 Дубль — актуальная карточка ниже»), а **новая (нижняя)**
   остаётся и получает список источников:
   - `rootSourceChatId/Title/Username` — самый ранний источник (показывается первым);
   - `extraSources` — остальные;
   - в подписи: `🧭 Парсер · <первый источник> · +N`.
   Порог схожести: фото — `QUEUE_MERGE_SIMILARITY` (0.85), видео —
   `VIDEO_MERGE_SIMILARITY` (0.92). Видео хешируется **по обложке** (первый кадр),
   ffmpeg не нужен.

Важно: карточки, ушедшие в `queued`/`published`, в склейке не участвуют — они
уже опубликованы.

## 8. Интерес из модерации

Вес источника (`weight`) определяет его позицию в выдаче (тай-брейкер к свежести).

**Растёт** от взятых постов: `boost = min(2, log2(1 + takenTotal))`.
**Остывает** от времени: `recency = 0.5^(дней_с_lastTakenAt / 21)`,
итого `base = 1 + boost × recency` — чтобы держаться в топе, канал надо
продолжать брать.

**Падает** от игноров:
- жёсткий (кнопка «🗑 Отклонить») — `−8%` за каждый, до `−80%`;
- мягкий (карточка истекла в бэклоге) — `−2%` за каждый;
- штраф тает за `RECOVER_DAYS` (7д) от `lastIgnoredAt`.

**Cooldown (пауза):** включается только если накопилось ≥ `COOLDOWN_MIN_HARD` (3)
жёстких игноров и вес упал ниже `PAUSE_WEIGHT` (0.35). Пауза — `COOLDOWN_DAYS` (7),
и каждая следующая пауза длиннее (гистерезис, `cooldownCount`). Когда пауза
истекает, штрафы делятся пополам, вес пересчитывается без повторной паузы.

**Очистка истории:** раз в сутки `refreshInterest()` делит `takenTotal` пополам у
каналов, которые не брали `TAKEN_STALE_DAYS` (45). Так старый успех не даёт
вечной форы.

Вес в ранжировании считается **на лету** (остывание действует сразу), а в меню —
по сохранённому `weight`, который обновляется ежедневным прогоном.

## 9. Чёрный список

Кнопка **«🚫 Исключить источник»** на карточке → подтверждение → `excludeSource`:
`excluded=true`, статус `disabled`. Такой канал:

- не собирается (`listCollectible` фильтрует `excluded`),
- не берётся в выдаче (кандидаты помечаются `rejected source-excluded`),
- не добавляется заново из discovery (`addSource` возвращает null, approve → `source-excluded`).

Вернуть можно из меню: **🚫 Исключённые → ↩️ N** (`restoreSource`) — сбрасывает
игноры и cooldown, канал снова активен.

## 10. Discovery (поиск каналов)

- Кросс-ссылки из собранных постов (forward-источники и `t.me`-ссылки) →
  `SourceCandidateEntity` с счётчиком `mentions`.
- Проверка: `t.me/s/` превью (просмотры, частота постов) + `channels.getFullChannel`
  (подписчики, ERR). Кап попыток `MAX_CHECK_ATTEMPTS` (5) → `rejected checks-exhausted`.
- Гейт: `err ≥ errMin` (0.25), `postsPerDay` 1–60, AI (если включён).
- Прошёл гейт → **сразу добавляется web-only** (`autoApprove`), без карточек и
  ручного подтверждения. Joins не выполняются (анти-бан).

## 11. Меню и команды

Меню «🧭 Парсер» (админ-меню, владелец):

| Пункт | Что делает |
|---|---|
| `Конвейер: 🟢/⚪️` | общий выключатель (env `PARSER_ENABLED=false` — жёстче) |
| `👴 Старый парсер: 🟢/⚪️` | приём постов обсерваторией (не гасит юзербот) |
| `ERR min` | порог ERR для discovery (пресеты 10/15/25/35%) |
| `Финал через N ч` | срок финальной оценки (4/8/12/24) |
| `AI (DeepSeek)` | классификация каналов/постов |
| `📥 Импорт подписок` | перенести текущие подписки аккаунта в реестр |
| `🏆 Популярные` | топ каналов по взятым/весу (пагинация) |
| `🚫 Исключённые` | чёрный список + возврат (пагинация) |
| `📚 Все источники` | все активные (пагинация) |
| `🔄 Обновить`, `↩️ Сброс` | перерисовать / сбросить настройки |

Команды/события:

- **`/more`** — канал-пост в канале предложки: добрать до 20 постов (сообщение
  команды удаляется). Дублируется кнопкой «🍲 Ещё 20» на последней карточке.
- Кнопки карточки: `▶️ Сейчас`, `📋 В очередь`, `🌙 В ночь (кринж)`,
  `🗑 Отклонить`, `🚫 Исключить источник` (+ `🍲 Ещё 20` на последней).
- После постановки в сетку кнопка с датой превращается в **«снять с публикации»**
  (с подтверждением): пост убирается из планировщика и возвращается в модерацию.
- Если пул пуст, `/more`/кнопка отвечают «🍲 Пока нечего показать» (в канале
  уведомление самоудаляется через 15с).

Админ-меню «Сетка публикаций»: пагинированный список неопубликованных постов
(ближайшие первыми, включая просроченные, ждущие cron), ссылки на посты и
снятие с подтверждением — можно снимать и не открывая карточку.

Темп выдачи ограничен: `DUMP_COOLDOWN_MINUTES` (5) между доборами и пауза
`~1.2с` между карточками; при Bot API 429 — retry с `retry_after`.

## 13. Крон-расписание (Europe/Moscow)

| Задача | Расписание | Что делает |
|---|---|---|
| sweep | `*/30` | history sweep по источникам |
| evaluate | `*/15` | форс + pre/final оценка + пауза при бэклоге |
| select | `*/20` | доставка **только форс-постов** + старение бэклога |
| discovery | `7 */3` | web-check новых каналов |
| stats | `0 5` | базлайны, подписчики, ERR, `refreshInterest`, `refreshCooldowns` |

`runJob` оборачивает каждую задачу метриками (`jobDuration`, `jobRuns`,
`jobLastSuccess`) и глотает ошибку, чтобы не ронять расписание.

## 14. Анти-бан и устойчивость

- Юзербот только читает; все MTProto-вызовы идут через `ParserMtprotoGuard`
  (FloodWait-конверт, jitter, терминальные ошибки → остановка + алерт).
- Bot API 429 обрабатывается retry с `retry_after` (до 3 попыток).
- Транзиентные сбои доставки (`send-failed`, `media-fetch-failed`) возвращают
  пост в пул (`rejectReason=null`), терминальные (`media-too-large`,
  `message-gone`, `source-missing`) → `rejected`, чтобы не циклиться.

## 16. Частые вопросы/траблшутинг

- **`/more` ничего не дал.** Пул `scored` пуст: свежие посты становятся доступны
  после pre-оценки (t+2ч); либо сработал cooldown 5 мин; либо `legacyEnabled`/
  конвейер выключен. Смотри в меню `⏳/🧮` и логи `Parser selector`.
- **Посты одного канала завалили выдачу.** Проверь `DUMP_PER_SOURCE_CAP`; кап
  ослабляется только на добор остатка.
- **Канал пропал.** Либо в чёрном списке (`🚫 Исключённые`), либо в cooldown
  (много отклонений), либо `idle`-статистика не обновилась.
- **Дубль не склеился.** Для ре-аплоадов срабатывает только перцептивный хеш;
  видео — по обложке, порог 0.92; разный первый кадр → не склеится.
- **Старый парсер снова льёт.** Тумблер «👴 Старый парсер» должен быть ⚪️
  (он гасит только приём постов обсерваторией, юзербот остаётся для нового).
